# MATH60610A.A2026_Projet1

## Overview

This project develops and evaluates a weekly machine-learning trading strategy for five foreign-exchange pairs:

-   EUR/USD
-   GBP/USD
-   CAD/USD
-   CHF/USD
-   JPY/USD

The objective is to forecast next-week FX returns, adjust those forecasts for predicted volatility, and build a cross-sectional long-short trading signal.

The project compares several regression methods, selects the best forecasting method separately for each currency pair through the **MIXT** specification, and applies **two logistic meta-classifiers**, one for the long leg and one for the short leg, to validate the trading signals.

All models are re-estimated every week on an **expanding window**. The final evaluation is conducted on an out-of-sample period of **260 weekly observations (five years)**, from 2021-09-09 to 2026-08-27.

## Data

The sample starts in **2004** and ends on **2026-08-27** (fixed in `Code/build_features.R`, so that the test period does not move when the data are downloaded again). All series are aligned to a weekly Thursday frequency: each weekly observation is the last value available on or before Thursday, provided it is at most 5 days old. Missing values are never interpolated, and any week with a missing return or feature is dropped.

### FX data

Daily adjusted prices are downloaded from Yahoo Finance for:

-   `EURUSD=X`
-   `GBPUSD=X`
-   `CADUSD=X`
-   `CHFUSD=X`
-   `JPYUSD=X`

Weekly log returns are computed from Thursday prices.

Daily FX prices are also used to construct weekly realized volatility:

$$
RV_t=\sqrt{\sum_{d\in(t-1,t]} r_d^2},
$$

where the interval runs from the previous Thursday (excluded) to the current Thursday (included).

### Macroeconomic data

The following series are downloaded from Yahoo Finance and converted to weekly log returns:

-   Gold (`GC=F`)
-   S&P 500 (`^GSPC`)
-   Crude oil (`CL=F`)

### Interest rates

Two-year and ten-year yields are collected for the United States and each currency area.

Sources include:

-   United States: FRED
-   Euro area: ECB
-   United Kingdom: Bank of England
-   Canada: raw CSV file from Bloomberg
-   Switzerland: raw CSV file from Bloomberg
-   Japan: raw CSV file from Bloomberg

The Effective Federal Funds Rate (DFF) is also downloaded from FRED and converted from an annualized percentage rate into a weekly log funding return. This rate is used to account for financing when the portfolio holds only one leg.

## Feature Engineering

Each currency pair is represented by **15 weekly predictors**.

### Interest-rate features (6)

-   2-year yield spread relative to the United States
-   10-year yield spread relative to the United States
-   Weekly change in the 2-year spread
-   Weekly change in the 10-year spread
-   Weekly change in the US 2-year yield
-   Weekly change in the US 10-year yield

### Macroeconomic features (3)

-   Gold weekly return
-   S&P 500 weekly return
-   Oil weekly return

### Momentum features (3)

-   Most recent weekly FX return
-   RSI
-   MACD

### Mean-reversion features (1)

-   Bollinger %B

### Volatility features (2)

-   4-week rolling standard deviation of weekly returns
-   12-week rolling standard deviation of weekly returns

All currency-pair feature matrices are restricted to a common date range before model estimation, and `Code/build_model.R` stops if the five pairs do not share exactly the same dates.

## Forecasting Models

The target is the **next-week FX return**.

The following forecasting approaches are compared:

1.  **Naive benchmark**\
    Uses the most recently observed return as the next-week forecast.

2.  **Linear regression**\
    OLS regression using the full predictor set.

3.  **Forward stepwise regression**\
    Variables are added sequentially according to the reduction in RSS, and the final model size is selected using BIC.

4.  **PCA regression**\
    Predictors are standardized, principal components are computed on the training sample only, and components with eigenvalues greater than 1 are retained.

5.  **Lasso**\
    Penalized regression with automatic variable selection.

6.  **Ridge**\
    Penalized regression that shrinks coefficients toward zero.

7.  **Elastic Net**\
    Combines Lasso and Ridge penalties.

    The penalized models use 5-fold cross-validation to select the penalty parameter $\lambda$.

8.  **Random Forest**\
    Uses 500 regression trees.

## Training, Validation, and Test Design

The split is strictly chronological.

The final **260 weeks** are reserved as the out-of-sample test period. The preceding **883 weeks** form the training sample.

Every model is estimated on an **expanding window**: to forecast week $t$, the model is re-estimated on all observations available before $t$. This is done over two periods:

-   **Validation**: the last **40%** of the training sample, starting from a model estimated on the first **60%**. The test period is never used.
-   **Test**: the final 260 weeks.

The validation forecasts are used to select the MIXT model and to provide the initial training sample of the meta-classifiers. The test forecasts are the ones traded in the backtest.

Walk-forward estimation runs in parallel (one task per method and currency pair) and takes about five minutes.

------------------------------------------------------------------------

## MIXT Model Selection

Rather than imposing the same forecasting method on every currency pair, the **MIXT** specification selects the candidate model with the highest validation $R^2$ separately for each pair.

The selected model can therefore differ across EUR/USD, GBP/USD, CAD/USD, CHF/USD, and JPY/USD.

MIXT is a model-selection rule rather than a separate forecasting algorithm: on the test period, it simply uses the expanding-window forecasts of the method selected for each pair.

------------------------------------------------------------------------

## Volatility and Sharpe Forecasts

A **GARCH(1,1)** model is estimated for each currency pair. Like the return models, its parameters are re-estimated every week on an expanding window. If an estimation fails to converge, the parameters of the previous week are kept.

The one-step-ahead conditional variance is

``` math
\hat{\sigma}_{i,t+1}^{2}
=
\omega_i
+
\alpha_i(r_{i,t}-\mu_i)^2
+
\beta_i\hat{\sigma}_{i,t}^{2}
```

Return forecasts are converted into risk-adjusted Sharpe signals using

``` math
\hat{s}_{i,t+1}
=
\frac{\hat{r}_{i,t+1}}{\hat{\sigma}_{i,t+1}}
```

The five currency pairs are ranked cross-sectionally each week using these predicted Sharpe signals.

------------------------------------------------------------------------

## Meta-Classification Filters

Two logistic meta-classifiers are used to validate the candidate trading legs:

-   a **long meta-classifier** for the candidate long position;
-   a **short meta-classifier** for the candidate short position.

Both classifiers use three signal-based predictors:

-   `Abs_Forecast`: absolute magnitude of the selected Sharpe forecast;
-   `Gap`: distance between the selected signal and the next closest signal;
-   `Dispersion`: cross-sectional standard deviation of the five Sharpe forecasts.

For $j \in \{L,S\}$, the classifier is

``` math
\hat{p}^{j}_{t+1}
=
\Pr(\mathrm{Win}^{j}_{t+1}=1)
=
\frac{1}
{1+\exp\left[-\left(
\beta_0^j
+\beta_1^j\mathrm{AbsForecast}_t
+\beta_2^j\mathrm{Gap}_t
+\beta_3^j\mathrm{Dispersion}_t
\right)\right]}
```

The classifiers are also re-estimated every week on an expanding sample: the validation legs, plus the test-period legs whose outcome is already known at the decision date.

The thresholds are fixed a priori at 0.50: a leg is kept when its estimated probability of winning is at least 50%. They are not optimized, because the validation sample contains too few trades to choose a threshold reliably.

-   **Long classifier:** $\tau_L = 0.50$
-   **Short classifier:** $\tau_S = 0.50$

`Code/build_model.R` also produces a threshold diagnostic table on the validation sample (`outputs/threshold_diagnostics.csv`). It is reported for information only and is not used to set the thresholds.

------------------------------------------------------------------------

## Trading Strategy

Each week:

1.  Compute the expanding-window MIXT return forecasts for the five FX pairs.
2.  Divide each return forecast by its GARCH volatility forecast.
3.  Rank the five pairs by predicted Sharpe.
4.  If all predicted Sharpe signals are non-positive, no trade is taken.
5.  Otherwise, the highest-Sharpe pair becomes the candidate long and the lowest-Sharpe pair becomes the candidate short.
6.  Each leg is executed only if its corresponding meta-classifier probability is at least its threshold.

Let $\ell$ denote the candidate long pair and $s$ the candidate short pair.

``` math
a_t=
\mathbf{1}
\left\{
\max_i \hat{s}_{i,t+1}>0,\,
\hat{p}^{L}_{t+1}\geq\tau_L
\right\}
```

``` math
b_t=
\mathbf{1}
\left\{
\max_i \hat{s}_{i,t+1}>0,\,
\hat{p}^{S}_{t+1}\geq\tau_S
\right\}
```

The weekly return is

``` math
R_{t+1}
=
a_t r_{\ell,t+1}
-
b_t r_{s,t+1}
-
(a_t-b_t)f_t
```

where $f_t$ is the weekly short-term funding rate derived from DFF.

Interpretation:

-   If both legs are accepted, the portfolio is long-short and self-financed.
-   If only the long leg is accepted, the strategy pays the funding rate.
-   If only the short leg is accepted, the short proceeds earn the funding rate.
-   If neither leg is accepted, the weekly return is zero.

The backtest does not include transaction costs or the interest-rate differential between currencies (carry), and the same rate is used for borrowing and lending.

------------------------------------------------------------------------

## Benchmarks and Evaluation

The final expanding-window MIXT strategy is compared with:

-   a **Naive** strategy, which applies the same ranking rule without meta-classifiers. Its Sharpe signal is last week's return divided by last week's realized volatility, so it estimates nothing;
-   the same MIXT ranking rule **without meta-classifiers**;
-   the other forecasting methods, each traded with the same ranking rule;
-   **1,000 random long-short strategies** generated over the same 260-week OOS period.

Performance statistics include:

-   cumulative return;
-   annualized return;
-   annualized volatility;
-   annualized Sharpe ratio;
-   maximum drawdown;
-   hit rate;
-   percentage of weeks traded.

The backtest also reports the out-of-sample performance of accepted versus rejected trades, the return by calendar year, and the metrics shown in the one-pager.

## Reproducibility

Random seeds are fixed where required, including penalized-regression cross-validation, Random Forest estimation, and the random-strategy benchmark. Results are identical with or without parallel estimation.

Model selection uses validation data only, and every forecast, volatility estimate, and meta-classifier decision made during the test period relies only on information available at the decision date. The final 260-week period is therefore kept strictly out of sample.

`run_data.R` downloads the data again each time it is run. The sample end date is fixed, so the test period does not move, but results can change slightly if a data provider revises its history.
